## Proposed new entries

| Concept | Proposed Owning Chapter | Scope Note |
|---|---|---|
| Lean UX canvas / assumptions worksheet | Lean UX (this chapter) | Full eight-box canvas (business problem through smallest experiment), construction order and dependency between boxes |
| Hypothesis-driven design statement | Lean UX (this chapter) | "We believe... for... will result in... we will know when..." template, falsifiability requirement |

| Build-Measure-Learn loop applied to design | Lean UX (this chapter) | Design-artifact-scoped application of the general Lean Startup loop; build = minimum design artifact, measure = small-batch usability signal, learn = canvas update. Explicitly distinct from the general business/product-scoped Lean Startup loop |
| Collaborative design studio practice | Lean UX (this chapter) | Four-round timeboxed cross-functional convergence method (individual divergence, critique, pair iteration, converge); a compressed application of Ideation's divergent/convergent mechanic, not a replacement for it |
| Outcome-over-output framing | Lean UX (this chapter) | Accountability model distinguishing measurable behavioral outcomes from shipped artifacts; drives how hypothesis statements and roadmap items are worded |
| Continuous small-batch validation cadence | Lean UX (this chapter) | Cycle-length and batch-size discipline (one riskiest assumption per short cycle) that prevents undetected error propagation across large validation rounds |

## Flag for merge-step attention (not a new-concept proposal, an observation)

- **General Lean Startup / Build-Measure-Learn concept has no formal
  CORE_CONCEPTS.md entry yet.** It is currently only *mentioned* at
  historical-evolution depth in [CH02_Research.md](../../02_Design_Thinking_and_Product_Management/CH02_Research.md#2-historical-evolution)

  and this chapter (CH13) links to CH02's mention as the recap target for the
  *general* (non-design-specific) loop, while claiming ownership only of the
  design-scoped application (see table above). Recommend the merge step add a
  formal ownership row for the general concept (owner: Research, per its
  earliest/deepest mention) so future chapters — particularly the
  not-yet-drafted Product Management "Experimentation" and "A/B Testing"
  chapters in this same part — have a clear recap target instead of
  re-deriving Lean Startup from scratch.
- **Dual-track Agile / discovery-delivery track pattern** is referenced by
  both CH02_Research.md (organizational-pattern mention) and this chapter's
  Section 7 (architecture-pattern elaboration). No full first-principles
  teaching of it exists yet in either chapter; this chapter's Section 7
  treatment is the deepest so far but is scoped specifically to Lean UX's
  architecture implications, not a general claim of ownership. Flagging for
  the merge step to decide whether a future chapter (possibly a Product
  Management "Roadmaps" or "Backlog" chapter) should own it in full.
